# 게스트 예약 변경·취소

마이그레이션 `202609250002_guest_management.sql`을 적용하고 배포한다.
기존 APP_URL과 CALENDAR_TOKEN_ENCRYPTION_KEY를 사용하므로 새 비밀 값은 필요 없다.
암호화 키로 용도를 구분한 HMAC을 생성한다. 키를 교체하면 기존 관리 링크도 무효가 된다.

- 예약 완료 화면 및 새 확인 메일에서 로그인 없이 관리 페이지로 이동한다.
- 기존 예약은 주최자 일정 목록의 `관리 링크 복사`로 전달한다. 기존 이메일을 일괄 재발송하지 않는다.
- 토큰은 URL fragment에 두고 API Authorization 헤더로 전달한다. 관리 페이지는 noindex/no-referrer다.
- 링크를 가진 사람은 해당 예약을 관리할 수 있으므로 공유하지 않는다. 예약 종료 30일 후 API 접근이 만료된다.
- 시작 전까지만 변경/취소할 수 있다. 취소는 반복해도 같은 결과이고, 변경은 요청 UUID로 중복 처리하지 않는다.
- 변경은 기존 예약 취소와 새 예약 생성이 하나의 DB 트랜잭션이다. 충돌 시 전체 롤백한다.
- 변경 전 예약은 replaced_by로 새 예약과 연결된다. 이전 이메일 링크에서도 최신 예약을 확인할 수 있다.
- 주최자 캘린더의 기존 이벤트를 지우고 새 이벤트를 등록한다. 실패는 calendar_pending에 남아 백그라운드 작업으로 재시도한다.
- 변경 이메일에는 변경 전/후 시간을 넣으며, 별도 취소 이메일은 발송하지 않는다. 일반 취소는 양쪽에 취소 이메일을 보낸다.
- 이메일 발송 재시도를 위해 `/api/cron/notifications`를 기존 CRON_SECRET으로 1분마다 호출한다. 리마인더 기능은 포함하지 않는다.

검증: `node node_modules/tsx/dist/cli.mjs --test tests/*.test.ts`, `npm run build`.
주요 검증 항목은 토큰 변조, 새 시간 충돌 시 기존 예약 보존, 요청 재시도,
취소 중복 알림 방지, 시작한 예약 거부, 소유자 외 링크 접근 거부다.
