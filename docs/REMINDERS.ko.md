# 예약 이메일 리마인더

- 예약 알림 화면에서 하루 전·1시간 전과 예약자·주최자 발송 여부를 설정합니다. 기본은 모두 켜짐이며 주최자의 모든 예약에 적용합니다.
- 게스트 메일에는 로그인 없이 예약을 변경·취소할 수 있는 개인 관리 링크가 포함됩니다.
- 기존 Supabase `moretime-notification-retries` 작업이 매분 `/api/cron/notifications`를 호출합니다([등록 방법](SCHEDULER.ko.md)). 새 예약 알림을 생성한 뒤 기존 발송 작업자가 처리합니다.
- `202609290001_reminders.sql`을 코드 배포 전에 적용해야 합니다. 추가 환경변수나 유료 스케줄러는 필요 없습니다.
- 발송 시점보다 늦게 생성된 예약에는 지난 리마인더를 보내지 않습니다. 하루 전 알림의 처리 기한은 1시간, 1시간 전 알림은 15분입니다. 장애가 이 기한을 넘기면 뒤늦게 발송하지 않습니다.
- 예약 변경은 새 예약 ID로 다시 계산합니다. 발송 직전에 예약 취소·시작 여부와 설정을 다시 확인합니다. 공급자에 이미 접수된 메일은 회수할 수 없습니다.
- 예약·종류·채널·수신자별 DB 고유 제약과 Resend 멱등성 키로 중복을 방지합니다. 일시적인 실패는 처리 기한 안에서 최대 3회 시도합니다.
- 과거 off 예약은 제외하고 dry-run 예약은 계속 모의 발송합니다. 문자·카카오 리마인더는 포함하지 않습니다.
- 두 수신자의 주소가 다르고 모든 설정을 켜면 예약당 확정 2통 + 리마인더 4통이 이메일 발송량에 포함됩니다. 같은 주소는 기존 확정 알림처럼 중복 발송하지 않습니다.

검증: `npm test`, `npm run build`. SQL 테스트는 PGlite에서 실제 마이그레이션을 실행해 시점·중복·설정·모드·권한을 확인합니다.
